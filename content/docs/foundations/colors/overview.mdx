## Color in med.o

Color is quiet and carries meaning. Most of a screen is neutral, the brand color marks what you can do, and status colors say what happened – in Light and Dark, and in your own brand.

## Layering model

Surfaces stack from the page inwards: at most three levels. Floating layers use surface/raised with elevation, not a darker color.

<Image src="/spec/colors/layering-model.svg" alt="The three surface levels in Light and in Dark: marker 1 on the page, 2 on a card, 3 on an inset area inside the card." width={824} height={268} ratio="original" fit="contain" radius="lg" />

1. Page – surface/canvas.
2. Container – surface/default: cards, panels, inputs.
3. Inset – surface/subtle: table headers, code blocks, hover rows.

## Implementing color

| Term | Definition |
| --- | --- |
| Theme | Light or Dark. It follows the system setting; `data-theme` on the root element overrides it. |
| Token | A named color with one value per theme, for example surface/default. |
| Role | What the token is for: surface, text, border, action, state, feedback. |
| Value | The palette color behind the token, per theme: white in Light, neutral-900 in Dark. |

## Interaction states

Filled controls have their own hover and pressed tokens. Transparent ones lay a state layer over their background.

| State | Filled controls | Transparent controls |
| --- | --- | --- |
| Hover | `action/*-hover` | `state/hover` |
| Pressed | `action/*-pressed` | `state/pressed` |
| Selected | `action/selected + text/brand` | `action/selected + text/brand` |
| Focus | `focus/ring on focus/halo` | `focus/ring on focus/halo` |
| Disabled | `action/disabled + text/disabled` | `text/disabled` |
